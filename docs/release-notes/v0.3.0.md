# Musa CAD v0.3.0

A follow-on to v0.2.0's annotation work, adding the **editing and inquiry** commands a
drafter reaches for constantly: STRETCH, the measurement commands, and dimension chaining.

> **Linux only.** This release ships the Linux AppImage. The Windows installer is built
> and verified separately on real Windows hardware (issue #6).

If you are coming from v0.1.0, read [`v0.2.0.md`](v0.2.0.md) too — that release added
dimension tolerances, GD&T, tables, dimension text control and the command line.

---

## New in v0.3.0

**STRETCH** (`S`) — the crossing-window modify command, and the one with no substitute in
the previous command set. Points **inside** the window move; the rest of each entity stays
anchored, so a partly-enclosed line or polyline is *deformed* rather than translated.
Objects defined by a single point (circle, arc, text, block reference, image, table, GD&T)
move entirely when that point is enclosed and are never deformed, exactly as in AutoCAD.

The useful part: **a dimension whose definition points are enclosed re-measures**. Stretch
a slot and its dimension together and the value follows, because dimensions have always
stored def points and computed their value from them.

**Inquiry commands** — `DIST` (DI), `ID`, `AREA` (AA) and `LIST` (LI). Previously the only
way to answer "how long is that?" was to draw a temporary dimension and delete it.

- `AREA` is exact for circles and uses the shoelace formula over the *same* tessellation
  the renderer draws, so the number matches what is on screen. An **open** object reports
  its length and says it has no area, rather than the area of the polygon you would get by
  closing it.
- `LIST` reports type, layer and defining parameters — and for a dimension, its **measured**
  value plus any text override, so `LIST` is also how you discover a dimension is
  overridden.

**DIMCONTINUE** (DCO) **and DIMBASELINE** (DBA) — chain the next dimension from the previous
one's second extension line, or stack from its first. The normal way to dimension a row of
holes. Both inherit the previous dimension's style and overrides, each pick is its own undo
group, and the chain **follows undo**: undo a dimension and the next pick continues from the
one before it.

## Fixed since v0.2.0

- **The AppImage did not bundle Qt's `offscreen` platform plugin**, so `musacad --plot`
  failed *inside the packaged artifact* with exit code 127 while the desktop launch worked
  perfectly. If you scripted plotting against the v0.2.0 AppImage, this is the fix.

## Compatibility

Native format is unchanged at **v20** — nothing in this release adds stored state. Files
written by v0.2.0 and v0.3.0 are interchangeable.

## Under the hood

- 455 tests, green under ASan/UBSan and ThreadSanitizer; release builds with zero warnings.
- Hot structs unchanged; scene draw calls still 4 (6 with drawing aids).
- `docs/ROADMAP.md` tracks what is still missing, grouped and mapped to issues #23–#33.

## Install (Linux)

```sh
chmod +x MusaCAD-0.3.0-x86_64.AppImage
./MusaCAD-0.3.0-x86_64.AppImage
```

No dependencies to install — Qt6 and the platform plugins are bundled. DWG import/export
additionally needs an external converter you install yourself (see `docs/BUILD.md`).
